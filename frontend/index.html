Bug Report

A real defect I found while testing DiagnoCare 2.0, written the way I report bugs.

HighP1Security · Access control✓ Fixed

Any logged-in user can open another patient's booking by changing the ID in the URL

Environment
DiagnoCare 2.0 (Django), local development build, Chrome
Preconditions
Two patient accounts: Patient A has a booking; you are logged in as Patient B.
Steps to reproduce
  1. Log in as Patient A, create a booking and note its ID in the URL: /booking/<id>/
  2. Log out, then log in as Patient B.
  3. Open /booking/<Patient A's id>/ directly in the address bar.
Expected result
404 Not Found. Patient B must not see Patient A's booking (test case TC-SEC-04).
Actual result
The page loads and shows Patient A's booking, including their phone number and address.
Impact
Personal data exposure: any account could read other patients' bookings just by trying different IDs.
Fix
Only the booking's patient, its diagnostic centre or an admin can open it; everyone else gets a 404.
Regression tests
test_other_patient_cannot_view, test_other_center_cannot_view, test_anonymous_is_sent_to_login — all passing.

Source: DiagnoCare 2.0 README (defect list), test case TC-SEC-04 and bookings/tests.py.

Completed · 2026B.Sc. Thesis

Deep Learning-Based Traffic Accident Detection and Collision Classification from CCTV Videos

Port City International University · with Md. Ibrahim Khalil · supervised by Nusratul Jannat

A two-stage system that finds the moment of an accident in CCTV video and classifies the collision type (head-on, rear-end, T-bone, sideswipe, single-vehicle), using two-stream ResNet50 features (appearance + optical flow) with BiGRU and BiLSTM sequence models on the ACCIDENT benchmark. On the official real-video test set it reached 50.0% accuracy, above the best published baseline (47.1%).

QA angle: results come from a locked test set with video-level splits and fixed seeds, so they are reproducible — and the evaluation openly reports the gap between synthetic and real videos.
